## 1. 项目简介

**DeepSeek Harness Android** 是一个 Android 壳应用，将 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（dsh）引擎以「内嵌 Termux 快照」的方式打包进单个 APK，实现**装完即用、完整离线可用**的移动端 Web Agent 体验。

### 关键特性

| 特性 | 说明 |
|------|------|
| **内嵌运行时** | 约 70MB 的 xz 快照（Node.js + Bash + coreutils + dsh + 插件），首启约 10 秒解压 |
| **零依赖运行** | 无需安装 Termux 或其他环境，快照解压到 app 私有目录即可直接运行 |
| **Web UI** | 系统 WebView 加载 `http://127.0.0.1:3080`，支持响应式布局 |
| **前台保活** | Foreground Service 保活 + 看门狗自动重启，引擎崩溃自动恢复 |
| **在线热更新** | 运行时可下载新快照并原子切换，无需重新安装 APK |
| **SAF 桥** | `pickDirectory` 将用户选择的目录映射为真实路径（如 `/storage/emulated/0/…`） |
| **多语言** | 中文 / 英文双语，设置页可切换 |
| **多镜像源** | 25+ 内置加速源，自动测速选最快；支持自定义前缀 |

### 二改（fork）新增功能

相比上游原版（[kelai141/dsh-mobile-apk](https://github.com/kelai141/dsh-mobile-apk)），本仓库增加了：

1. **加固的引擎看门狗**：连续失败容错计数 + 重启退避，避免无限快速重启；Web 页面打开期间豁免自动重启
2. **修复 Web 保存配置文件导致引擎卡死**
3. **存储占用统计与一键清理**
4. **主页状态卡**（引擎延迟 / 运行时长 / 数据占用 / 缓存大小）
5. **首次进入引导页**（含权限注意事项提示）
6. **权限管理页**（通知 / 文件访问 / 网络权限状态与去授权入口）
7. **查看引擎日志入口**
8. **关于页单列纵向布局**（所有操作按钮完整可见）
9. **终端 ASCII 进度条**（下载/安装进度，实时原地刷新）
10. **引擎重启优化**（已就绪后点击「重启引擎」直接重启，不重复下载）

## 2. 核心概念

### 运行时快照（Snapshot）

应用内置一个约 70MB 的 `snapshot.tar.xz` 压缩包，包含：

- **Node.js**（JS 运行时）
- **Bash + coreutils**（命令执行环境）
- **dsh 引擎**（`@deepseek-ai/dsh`）
- **常用插件**（预装）

首次启动时解压至 `<app>/files/usr`，后续运行直接复用，无需联网。

### 目录结构

```
应用私有目录（filesDir）/
├── usr/                  ← 解压后的运行时环境（Node + Bash + dsh）
│   ├── bin/node          ← 引擎入口
│   ├── bin/bash          ← bash 解释器
│   └── lib/…             ← 系统库
├── home/                 ← DSH_HOME（运行时工作目录）
│   └── .dsh/             ← dsh 配置与数据
│       ├── settings.yaml ← 引擎配置
│       ├── profiles/     ← 会话配置
│       ├── sessions/     ← 对话历史
│       ├── web-slots/    ← WebView localStorage 宿主化落盘
│       └── …
└── logs/
    └── engine.log        ← 引擎运行日志（实时输出）
```

公共目录（`Documents/dshdata`）仅作为用户主动导出仓库，运行时数据全部在私有域。

### 关键配置文件

| 文件 | 位置 | 说明 |
|------|------|------|
| `snapshot.tar.xz` | `app/src/main/assets/` | 内置运行时快照（构建时必须存在） |
| `snapshot.sha256` | `app/src/main/assets/` | 快照指纹，用于检测是否需要重解压 |
| `settings.yaml` | `files/home/.dsh/` | 引擎运行时配置 |
| `engine.log` | `files/logs/` | 引擎标准输出日志 |
| `terminal.log` | `files/logs/` | 应用终端日志 |
| `.snapshot-online` | `files/` | 在线更新标记（防止误覆盖回出厂快照） |
| `.snapshot-fingerprint` | `files/` | 内嵌快照指纹缓存 |
| `.private-layout` | `files/home/.dsh/` | 标记是否已迁移为私有数据布局 |

## 3. 编译构建

### 环境要求

- **JDK**：17+
- **Android SDK**：`compileSdk 36`
- **Gradle**：8.11.1（由 wrapper 提供，无需手动安装）
- **keystore.properties**（可选）：签名配置

### 构建步骤

#### Step 1：准备运行时快照

快照是**必须的**，约 70MB，从 GitHub Releases 下载或自行编译：

```bash
# 方式 A：从 GitHub Releases 下载（推荐）
mkdir -p app/src/main/assets
curl -L -o app/src/main/assets/snapshot.tar.xz \
  "https://github.com/YOYOFeelings/DeepSeek-Harness-Android/releases/latest/download/snapshot-x86_64.tar.xz"
curl -L -o app/src/main/assets/snapshot.sha256 \
  "https://github.com/YOYOFeelings/DeepSeek-Harness-Android/releases/latest/download/snapshot.sha256"

# 方式 B：在 Termux 设备上自打
# bash scripts/make-snapshot.sh   # 需安装依赖后执行
```

#### Step 2：签名配置（可选）

创建 `keystore.properties`（与 `build.gradle.kts` 同级）：

```properties
storeFile=keystore/release.jks
storePassword=your_password
keyAlias=dsh
keyPassword=your_password
```

`keystore/release.jks` 需提前生成：

```bash
keytool -genkey -v -keystore keystore/release.jks \
  -alias dsh -keyalg RSA -keysize 2048 -validity 10000
```

#### Step 3：编译

```bash
# Debug 包（未签名 / 使用 keystore 签名）
./gradlew assembleDebug

# Release 包（需 keystore）
./gradlew assembleRelease
```

构建产物位于项目根目录：
- Debug：`deepseek-harness-0.11.7-debug.apk`
- Release：`deepseek-harness-0.11.7-release.apk`

#### 常见问题

| 错误 | 原因 | 解决 |
|------|------|------|
| `缺少运行时快照 assets/snapshot.tar.xz` | 未放置快照文件 | 下载快照到 `app/src/main/assets/` |
| `Gradle daemon was killed` | JVM 内存不足 | 增大 `gradle.properties` 中 `org.gradle.jvmargs` |
| `目标设备架构与快照不匹配` | arm64 设备装了 x86_64 快照 | 选择匹配的 ABI 快照，或保持联网让应用自动下载 |

## 4. 安装与首次使用

### 安装

1. 下载/构建 APK 后通过 `adb install` 或传输到设备安装
2. 授予**安装未知应用**权限（如需）
3. 首次启动时会触发安装引导流程

### 首次引导流程

首次启动（未看过引导页）→ 展示全屏引导页 → 点击「开始使用」后自动执行：

```
解压内嵌运行时（约 70MB）
  ↓
写入 dsh 出厂配置（settings.yaml + profiles）
  ↓
检查在线更新（多镜像源测速 → 下载最新版快照 → SHA256 校验 → 原子切换）
  ↓
启动 dsh 引擎（node + bash，监听 127.0.0.1:3080）
  ↓
启动 Foreground Service 保活 + 看门狗
  ↓
进入终端主页（WebView 打开 Web UI）
```

整个流程实时日志输出到**终端页**，可查看进度。

### 引导页关键信息

引导页会提示以下权限的注意事项：
- **通知权限**（POST_NOTIFICATIONS）：引擎保活通知
- **所有文件访问权限**（MANAGE_EXTERNAL_STORAGE）：供引擎读写用户选定的外部工作目录
- **网络权限**（INTERNET）：引擎探测 + 在线更新

## 5. 功能详解

### 5.1 底部导航

| 页签 | 功能 |
|------|------|
| **主页** | 公告、引擎状态卡、操作入口（进入 Web / 工作目录 / 更新 / 重启引擎等） |
| **终端** | 统一日志控制台（所有流程日志都输出到这里） |
| **插件** | 插件列表、导入 / 卸载 / 启用停用管理 |
| **设置** | 通用、更新源、存储、权限、外观 |

横屏/大屏（宽 ≥ 600dp）自动切换为**左侧导航栏**，竖屏为**底部导航栏**。

### 5.2 主页操作按钮

| 按钮 | 功能 |
|------|------|
| **进入 Web** | 打开 WebView 覆盖层，加载 `http://127.0.0.1:3080` |
| **工作目录** | 调用 SAF `pickDirectory`，选择外部工作目录 |
| **检查并应用更新** | 运行运行时在线更新（测速 → 下载 → 校验 → 切换） |
| **安装环境** | 在线安装/升级 Node.js 或 Python 运行时环境 |
| **检查应用更新** | 检查 APK 自身版本是否有新版本 |
| **重启引擎** | 清空旧日志 → 重启 dsh 引擎进程 |
| **清理缓存** | 清理 `cacheDir` + WebView 缓存 |
| **重载公告** | 重新从 GitHub 拉取公告内容 |

### 5.3 设置页子页面

#### 通用
- 语言切换（中文 / English）
- 启动时自动启动引擎开关
- 屏幕常亮开关

#### 更新源
- 显示当前激活源（含延迟测速结果）
- 添加自定义加速源（输入 URL 前缀）
- 下载历史记录

#### 存储
- 引擎数据占用统计
- 缓存大小统计
- 一键清理缓存
- 引擎日志查看（跳转到终端页）

#### 权限
- 通知权限状态 + 去设置授权入口
- 所有文件访问权限状态 + 去设置授权入口
- 网络权限状态

#### 外观
- 背景类型：默认色 / 纯色 / 渐变色 / 图片
- 背景图片：相册选取 / URL 下载 / 随机获取
- 明暗遮罩强度（0–80）
- 模糊效果开关

### 5.4 插件管理

在「插件」页可：
- **导入插件**：从本地选择 `.tgz` 压缩包，自动解压到 `usr/lib/node_modules/`
- **卸载插件**：删除对应目录（二次确认）
- **启用 / 停用**：将目录重命名为 `*.disabled`，Node.js 不再解析，重启引擎生效

> 注意：全局 node_modules 中的核心插件（如 `@deepseek-ai/dsh`）不可卸载。

## 6. 在线更新机制

### 更新源架构

```
GitHub Releases 最新标签
       │
       ├── MANIFEST.txt（发布清单）
       │     格式：sha256  filename  size（每行一个资产）
       │
       ├── snapshot-arm64.tar.xz   ← ARM64 设备选用
       └── snapshot-x86_64.tar.xz  ← x86_64 设备选用
```

### 更新流程

1. 拉取 `MANIFEST.txt`（多镜像源自动回退）
2. 按设备 **ABI** 匹配对应快照
3. 经所选更新源下载（内置 25+ 国内加速源 + 官方直连）
4. **SHA-256 校验**通过后解压到 staging 目录
5. **原子切换**：`usr` → `usr-old` → 新 `usr`
6. 杀掉旧引擎进程
7. 看门狗用新运行时自动重启引擎
8. 写 `.snapshot-online` 标记，防止下次启动误覆盖回内嵌快照

### 多镜像源机制

- **自动模式**（默认）：每次更新时逐源测速，选延迟最低的源下载
- **手动模式**：用户在设置页指定某个特定加速源
- **回退机制**：当前源下载失败时自动切换下一个可用源
- **自定义前缀**：可在设置页输入自己的加速 URL 前缀

### 内置更新源（部分）

| ID | 名称 | 前缀 |
|----|------|------|
| `akaere` | cdn.akaere.online | `https://cdn.akaere.online/` |
| `gh-proxy` | gh-proxy.com | `https://gh-proxy.com/` |
| `official` | 官方直连 | （无前缀） |
| `ghproxy.net` | ghproxy.net | `https://ghproxy.net/` |
| …（共 25+ 个） | | |

## 7. 桥协议（Android Bridge）

WebView 通过 `window.androidBridge` 与壳应用通信，协议版本 `"1.0"`。

### 接口一览

| 方法 | 签名 | 说明 |
|------|------|------|
| `version` | getter → `String` | 桥协议版本号 `"1.0"` |
| `checkEngine` | `() → String` | 探测引擎，返回 `{running, latencyMs}` JSON |
| `keepScreenOn` | `(enable: Boolean)` | 控制屏幕常亮 |
| `showNotification` | `(title, text)` | 发送通知（测试通道） |
| `pickDirectory` | `(callbackId: String)` | 选择目录；结果异步回调 `onDirectoryPicked(callbackId, path)` |
| `saveConfig` | `(key, value) → Boolean` | 持久化键值到 SharedPreferences |
| `readConfig` | `(key) → String` | 读取配置值 |
| `saveSettingsYaml` | `(yaml) → Boolean` | 将 settings.yaml 全文写入 DSH_HOME |
| `saveSlotConfig` | `(slot, content) → Boolean` | 写槽位配置到 `DSH_HOME/.dsh/web-slots/<slot>.json` |
| `readSlotConfig` | `(slot) → String?` | 读槽位配置 |
| `removeSlotConfig` | `(slot) → Boolean` | 删除槽位配置 |
| `clearSlotConfigs` | `() → Boolean` | 清空全部槽位配置 |
| `downloadDebugLogs` | `() → Unit` | 导出调试日志 zip |
| `hasAllFilesAccess` | getter → `Boolean` | 是否已获得所有文件访问权限 |
| `requestAllFilesAccess` | `() → Unit` | 跳转系统设置申请权限 |
| `getPickToken` | getter → `String?` | 目录选择鉴权 token |

### localStorage 宿主化

由于 WebView 中 `localStorage` 可能因存储禁用或配额超限而静默失败，APK 通过注入 `storageShimScript` 将页面 `window.localStorage` 代理到上述槽位桥方法（落盘到 `DSH_HOME/.dsh/web-slots/`），天然免配额且引擎可见。桥不可用时静默回退到原生 `localStorage`。

### SAF 目录桥

`pickDirectory` 回调通过系统 `ACTION_OPEN_DOCUMENT_TREE` 调起文件管理器，返回的 URI 经 `DocumentsContract` 解码为真实路径（如 `primary:Projects/myproj` → `/storage/emulated/0/Projects/myproj`）。

## 8. 故障排查

### 8.1 引擎启动失败

**常见原因**：
- 内嵌快照架构与设备 ABI 不匹配（如 arm64 设备装了 x86_64 快照）
- `termux-exec` preload 库缺失
- SELinux 拒绝执行 app-data ELF

**排查步骤**：
1. 查看终端页日志（`----- engine.log 末尾 -----`）
2. 点击「检查并应用更新」——在线下载匹配架构快照可修复架构问题
3. 在设置 → 存储 → 查看引擎日志
4. 点击「重启引擎」重试

**错误报告**：引擎启动失败弹窗支持一键下载错误报告（含设备 ABI、快照架构、日志尾部），可用于问题反馈。

### 8.2 在线更新失败

- 检查网络连接
- 进入设置 → 更新 → 更换加速源
- 点击「添加自定义源」输入可用的 CDN 前缀
- 全部失败时尝试使用官方直连（`official` 源）

### 8.3 配置文件保存不生效

原因：Web UI 保存的配置依赖 `localStorage`，在 WebView 环境中可能失败。  
解决：APK 已自动接管 `localStorage` 到文件落盘，若仍不生效请检查：
- 设置 → 权限 → 文件访问权限
- 工作目录是否有写入权限

### 8.4 引擎卡死

- 点击「重启引擎」
- 若持续卡死，清除缓存（设置 → 存储 → 清理缓存）后重试
- 查看引擎日志定位具体错误

### 8.5 日志查找

| 日志类型 | 路径 | 查看方式 |
|----------|------|----------|
| 终端日志 | `files/logs/terminal.log` | 终端页直接显示 |
| 引擎日志 | `files/logs/engine.log` | 设置 → 存储 → 查看引擎日志 |
| 错误报告 | 导出到 `files/logs/` | 引擎失败弹窗 → 下载报告 |

## 9. 安全说明

### 权限说明

| 权限 | 用途 | 是否必须 |
|------|------|----------|
| `INTERNET` | WebView 加载 + 引擎端口探测 + 在线更新 | ✅ 必须 |
| `POST_NOTIFICATIONS` | 保活通知（Android 13+ 运行时请求） | 推荐 |
| `FOREGROUND_SERVICE` | 保活前台服务 | ✅ 必须 |
| `FOREGROUND_SERVICE_DATA_SYNC` | 前台服务类型声明 | ✅ 必须 |
| `MANAGE_EXTERNAL_STORAGE` | 外部工作区读写 | 按需（使用外部目录时） |
| `REQUEST_INSTALL_PACKAGES` | APK 自更新安装 | 按需（开启自动更新时） |

### 数据安全

- 所有运行时数据（sessions、配置、插件）存储在 **app 私有目录**（`filesDir`），不依赖公共存储
- 用户选定的工作目录通过 SAF 授权后映射为真实路径，引擎可直接读写
- 桥接配置键名校验：拒绝路径注入字符（`..`、`/`），长度 ≤ 128，仅允许 `[A-Za-z0-9._-]`
- 槽位配置文件名将非法字符替换为下划线，防止路径穿越
